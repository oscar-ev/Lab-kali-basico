Pentest Básico com Docker

Um ambiente isolado, montado na sua própria máquina, para explorar na prática as ferramentas essenciais de segurança ofensiva.

Ferramentas: nmap · curl Alvo: localhost:8080 Duração: ~60 min

Aviso legal

Todos os testes são feitos dentro da sua própria máquina, em containers isolados. Usar essas ferramentas contra sistemas de terceiros sem autorização é crime pela Lei 12.737/2012 (Lei Carolina Dieckmann). Execute apenas o que está neste roteiro.

Regra de ouro — um comando por vez

O PowerShell dos laboratórios da UMC não aceita dois comandos na mesma linha. Por isso, cada bloco de código abaixo é um único comando. Rode um bloco de cada vez (use o botão copiar), aperte Enter e espere terminar. Nunca junte comandos com &&, | ou ; — se aparecer erro de sintaxe, foi mais de uma linha colada junta.

O que é cada ferramenta?

Cinco peças compõem o laboratório. Entenda o papel de cada uma antes de começar.

🐳Dockerinfraestrutura
Cria "mini-computadores" isolados (os containers) dentro do seu Windows. Cada um é separado do resto — se algo der errado, não afeta o seu PC.
🎯DVWAalvo
O site que vamos atacar. Sigla de Damn Vulnerable Web Application: um site feito de propósito cheio de falhas, para treino. Roda na porta 8080.
🐉Kali Linuxatacante
O "computador do analista". Um Linux repleto de ferramentas de segurança, noutro container. É daqui que disparamos os testes contra o alvo.
🔍nmapferramenta
Um scanner de rede. Verifica a máquina alvo e descobre quais portas estão abertas e qual programa (e versão) roda em cada uma.
🌐curlferramenta
Um navegador sem tela. Faz pedidos a um site e mostra a resposta crua — cabeçalhos HTTP e HTML — no terminal, revelando o que o navegador esconde.
🪟PowerShellterminal
O terminal do Windows, onde você liga e desliga os containers. Não confunda com o terminal do Kali — o roteiro sempre indica onde rodar.

Como as peças se encaixam

Os dois containers ficam na mesma máquina; o Kali enxerga o DVWA como um site na rede.

Entenda a ideia

Você é, ao mesmo tempo, o atacante (Kali) e o dono do alvo (DVWA). Como tudo está na sua máquina e com sua permissão, o exercício é 100% legal e seguro.
PRÉ Verificar o Docker

Abra o PowerShell (não precisa ser administrador) e rode o comando abaixo.

🪟 PowerShell — sua máquina
PowerShell · Windows
PS>docker version
Client: Docker Engine — versão XX.X
Server: Docker Engine — versão XX.X ← precisa aparecer esta linha

Se aparecerem as duas linhas, Client e Server, com versões, está tudo certo. Se der erro, abra o Docker Desktop, espere o ícone da baleia ficar verde e tente de novo.

00 Subir o laboratório ~5 min

Dois comandos. Rode o primeiro, espere terminar, só então rode o segundo.

Resultado esperado Ao final, o DVWA estará no ar em localhost:8080 e você estará com um terminal aberto dentro do Kali.
0.1Subir o site alvo (DVWA)
🪟 PowerShell — sua máquina
PowerShell · Windows
PS>docker run -d --name alvo-web -p 8080:80 vulnerables/web-dvwa
a3f1c9e8d2... ← apareceu um código longo? Funcionou.

docker run cria e liga um container. -d deixa rodando em segundo plano. --name alvo-web dá um apelido ao container. -p 8080:80 liga a porta 8080 do seu PC à porta 80 interna, onde o site mora.

Na primeira vez demora

Na estreia, o Docker baixa a imagem (~1 GB) antes de ligar — pode levar alguns minutos. Nas próximas é quase instantâneo, porque fica salvo.
0.2Abrir o Kali Linux (terminal do atacante)
🪟 PowerShell — sua máquina
PowerShell · Windows
PS>docker run -it --name kali --network host kalilinux/kali-rolling bash
root@kali:/# ← o prompt mudou: agora você está dentro do Kali.

-it abre um terminal interativo dentro do container. --network host faz o Kali enxergar a rede do seu PC — é assim que ele alcança o localhost:8080 do alvo. bash é o terminal que abre.

Atenção ao início da linha

Quando começar com root@kali, você está no Kali. Quando começar com PS>, você está no PowerShell. Cada passo abaixo indica onde rodar.

Confira o alvo

Abra o navegador em http://localhost:8080. Se a tela de login do DVWA aparecer, o alvo está no ar.
01 Reconhecimento com nmap ~15 min

Antes de atacar, o analista mapeia o alvo: quais portas estão abertas e o que roda em cada uma.

O que você vai descobrir Quais portas estão abertas, qual serviço roda em cada uma e a versão exata do software — a base de qualquer ataque ou defesa.
1.1Atualizar a lista de programas do Kali
🐉 Kali — root@kali
Kali · root@kali
#apt update
Espere terminar — vai aparecer bastante texto, é normal.

apt update atualiza a lista de programas disponíveis. É só a lista; ainda não instala nada.

1.2Instalar o nmap e o curl
🐉 Kali — root@kali
Kali · root@kali
#apt install -y nmap curl
Espere terminar (~2 min).

apt install nmap curl instala as duas ferramentas de uma vez. -y responde "sim" automaticamente, para não travar pedindo confirmação.

1.3Varredura básica — quais portas estão abertas?
🐉 Kali — root@kali
Kali · root@kali
#nmap localhost
PORT STATE SERVICE 8080/tcp open http-proxy ← nosso alvo

nmap localhost testa as 1000 portas mais comuns. open significa que a porta está aberta e aceitando conexões. A 8080 é onde o DVWA roda.

1.4Descobrir a versão do serviço (-sV)
🐉 Kali — root@kali
Kali · root@kali
#nmap -sV -p 8080 localhost
8080/tcp open http Apache httpd 2.4.x ← versão revelada

-sV pede ao nmap a versão exata do programa na porta. -p 8080 foca só nessa porta, deixando mais rápido.

Por que a versão importa?

Cada versão tem falhas públicas catalogadas no banco CVE (cve.mitre.org). Saber a versão é o primeiro passo para saber como atacar — ou como se defender.
1.5Scan com scripts e salvar em arquivo
🐉 Kali — root@kali
Kali · root@kali
#nmap -sV -sC -p 8080 localhost -oN /tmp/scan-nmap.txt
http-title: Damn Vulnerable Web Application http-methods: GET POST HEAD OPTIONS

-sC roda scripts automáticos: título da página, métodos HTTP aceitos e mais. -oN /tmp/scan-nmap.txt salva tudo num arquivo — você vai precisar dele no relatório.

02 Inspeção manual com curl ~20 min

O curl mostra a resposta crua do servidor — como inspecionar o envelope das mensagens entre navegador e site.

O que você vai descobrir Os cabeçalhos HTTP revelam tecnologias, versões e proteções de segurança ausentes — direto no terminal, sem abrir o navegador.
2.1Ver os cabeçalhos do servidor
🐉 Kali — root@kali
Kali · root@kali
#curl -I http://localhost:8080
HTTP/1.1 302 Found Server: Apache/2.4.x ← versão exposta X-Powered-By: PHP/7.x ← linguagem exposta
(sem Strict-Transport-Security · sem X-Frame-Options · sem Content-Security-Policy)

-I (i maiúsculo) pede só os cabeçalhos, sem baixar a página inteira. Cada proteção que não aparece na resposta é um cabeçalho de segurança ausente — e isso é uma vulnerabilidade real.

Cabeçalho ausente = achado

Todo cabeçalho de segurança que falta vira um item no relatório, criticidade Médio. Anote quais faltavam e o que cada um protegeria.
2.2Ver o HTML da página de login
🐉 Kali — root@kali
Kali · root@kali
#curl http://localhost:8080/login.php
<form action="login.php" method="post"> ...

Sem o -I, o curl baixa o HTML inteiro. Procure as tags form, input e action — mostram como o formulário de login funciona por dentro.

2.3Testar o login com a senha padrão

Testamos se o site aceita admin / password. Como não podemos usar | no PowerShell, fazemos em dois passos: salvar a resposta num arquivo e depois lê-la.

🐉 Passo A — Kali
Kali · root@kali — uma linha só
#curl -i -s -d "username=admin&password=password&Login=Login" http://localhost:8080/login.php -o /tmp/login-teste.txt
Sem resposta na tela = deu certo, foi tudo para o arquivo.

-d "..." envia os dados do formulário (o curl entende como POST). -i inclui os cabeçalhos da resposta. -s modo silencioso. -o /tmp/login-teste.txt grava no arquivo em vez da tela.

🐉 Passo B — Kali
Kali · root@kali
#grep Location /tmp/login-teste.txt
Location: index.php ← login aceito! A senha padrão funcionou.

grep Location /tmp/login-teste.txt procura a palavra Location dentro do arquivo salvo. Se a resposta for index.php, o DVWA redirecionou para a área logada — ou seja, o login deu certo. Se fosse login.php, teria falhado.

Achado crítico — credencial padrão ativa

O sistema aceita admin / password sem exigir troca. Qualquer pessoa entra sem esforço. No relatório, criticidade Crítico.
2.4Salvar os cabeçalhos como evidência
🐉 Kali — root@kali
Kali · root@kali
#curl -I http://localhost:8080 -o /tmp/scan-curl.txt
Cabeçalhos salvos em /tmp/scan-curl.txt

-o /tmp/scan-curl.txt grava os cabeçalhos num arquivo. Usamos -o no lugar do antigo > — faz a mesma coisa e é mais à prova de erro.

03 Juntar as evidências ~5 min

Reúne o resultado do nmap e do curl num único arquivo para anexar ao relatório.

3.1Juntar os arquivos de saída
🐉 Kali — root@kali
Kali · root@kali
#cat /tmp/scan-nmap.txt /tmp/scan-curl.txt /tmp/login-teste.txt > /tmp/evidencias.txt
Arquivo único criado em /tmp/evidencias.txt

cat lê os três arquivos e o > grava tudo junto em /tmp/evidencias.txt. Esse > roda dentro do Kali (bash), não no PowerShell — aqui funciona sem problema.

3.2Conferir o conteúdo
🐉 Kali — root@kali
Kali · root@kali
#cat /tmp/evidencias.txt
Deve aparecer o resultado do nmap, do curl e do teste de login.

Se aparecer o conteúdo dos três scans, está tudo certo. Esse arquivo é a sua evidência.

Como levar as evidências para o relatório

Rode cat /tmp/evidencias.txt, selecione o texto que apareceu na tela, copie (Ctrl+C) e cole no relatório.
